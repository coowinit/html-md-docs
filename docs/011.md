# 1. TXT 和 JSON 的区别

上一章 TXT 保存的数据类似：

```text
2026-08-16 10:00:00 | Hello
2026-08-16 10:01:00 | PHP
```

虽然简单，但 PHP 并不知道：

```text
哪一部分是姓名
哪一部分是时间
哪一部分是留言
```

除非自己定义并解析格式。

JSON 可以明确保存字段：

```json
{
  "id": 1,
  "name": "Tom",
  "message": "Hello",
  "created_at": "2026-08-16 10:00:00"
}
```

因此它属于：

```text
结构化数据
```

---

# 2. PHP 数组

PHP 中的一条记录：

```php
$message = [
    'id' => 1,
    'name' => 'Tom',
    'message' => 'Hello',
];
```

这是：

```text
关联数组
```

多条记录：

```php
$messages = [
    [...],
    [...],
    [...],
];
```

就是：

```text
多维数组
```

---

# 3. json_encode()

PHP 数组转 JSON：

```php
$json = json_encode($messages);
```

流程：

```text
PHP Array
↓
json_encode()
↓
JSON String
```

# 4. JSON_UNESCAPED_UNICODE

默认情况下，中文可能被转换成 Unicode 转义形式。

因此本实验使用：

```php
JSON_UNESCAPED_UNICODE
```

这样：

```text
你好
```

可以直接保留为中文。

---

# 5. JSON_PRETTY_PRINT

本实验还使用：

```php
JSON_PRETTY_PRINT
```

这样 JSON 文件会自动缩进，更方便人工阅读。

例如：

```json
[
    {
        "id": 1,
        "name": "Tom"
    }
]
```

比压缩成一整行更适合学习和调试。

# 6. 保存 JSON

流程：

```php
$json = json_encode(...);

file_put_contents(
    $dataFile,
    $json,
    LOCK_EX
);
```

这里和上一章一样：

```text
JSON 最终仍然是字符串
```

因此还是使用：

```php
file_put_contents()
```

写入文件。

---

# 7. json_decode()

读取：

```php
$json = file_get_contents($dataFile);
```

此时得到的是：

```text
JSON 字符串
```

再：

```php
$data = json_decode($json, true);
```

转换为 PHP 数组。

流程：

```text
JSON String
↓
json_decode()
↓
PHP Array
```

---

# 8. 为什么第二个参数写 true

写：

```php
json_decode($json, true)
```

第二个参数：

```php
true
```

表示希望结果转换为：

```text
PHP 关联数组
```

于是可以：

```php
$item['name']
```

如果不写 `true`，默认更多会转换成 PHP 对象。

对象会在后面的 OOP 阶段再研究。

当前阶段统一使用数组，更容易理解。

$messages[] = [

这里：

```php

```

---

# 10. 再把整个数组保存回文件

新增记录后：

```text
原数组
+
新记录
↓
新的完整数组
↓
json_encode()
↓
覆盖 messages.json
```

注意这里和上一章 TXT 不同。

TXT 使用：

```php
FILE_APPEND
```

逐行追加。

JSON 更常见的简单做法是：

```text
读取整个 JSON
↓
转换为数组
↓
修改数组
↓
重新编码
↓
整体写回文件
```

---

# 11. 为什么 JSON 不直接 FILE_APPEND

假设文件本来是：

```json
[
    {
        "id": 1
    }
]
```

如果直接在末尾追加：

```json
{
    "id": 2
}
```

可能变成：

```json
[
    {
        "id": 1
    }
]
{
    "id": 2
}
```

这就不是合法的单个 JSON 文档。

因此不能像普通 TXT 那样随意追加字符串。

# 14. JSON 为什么很重要

JSON 是 Web 开发中非常重要的数据格式。

常见场景：

```text
配置文件
前后端数据传输
API
Ajax
JavaScript fetch()
数据导入导出
简单本地数据
```

以后会经常看到：

```text
JavaScript Object
↕
JSON
↕
PHP Array
```

---

# 15. 与 JavaScript 的关系

JavaScript：

```js
JSON.stringify(data)
JSON.parse(json)
```

PHP：

```php
json_encode($data)
json_decode($json, true)
```

因此可以形成对应关系：

```text
JavaScript Object
↓ JSON.stringify()
JSON
↓ json_decode()
PHP Array
```

反过来：

```text
PHP Array
↓ json_encode()
JSON
↓ JSON.parse()
JavaScript Object
```

这也是后面 Ajax / API 的基础。

---

# 16. 与 API 的关系

后面的 PHP JSON API，本质上就是：

```php
header('Content-Type: application/json');

echo json_encode($data);
```

也就是说：

```text
本章
PHP → JSON 文件

后面
PHP → JSON HTTP 响应
```

核心仍然是：

```php
json_encode()
```

---

# 17. JSON 适合什么

比较适合：

```text
少量结构化数据
配置
导入导出
缓存
简单项目
API 数据
```

---

# 18. JSON 不适合替代数据库的场景

如果开始需要：

```text
大量数据
复杂搜索
多条件筛选
排序
分页
关联关系
频繁修改
多人并发
```

JSON 文件维护会越来越困难。

这也是后面需要 SQLite / MySQL 的原因。
