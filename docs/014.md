# 实验 14：PHP 文件上传

本实验通过一个最小图片上传功能，学习 PHP 如何接收、验证和保存浏览器上传的文件。

> 本实验只允许 JPG、PNG、WebP 三种图片格式，并限制最大 2 MB。

---

## 实验目标

完成本实验后，应能够理解：

- `enctype="multipart/form-data"`
- `$_FILES`
- 上传临时文件
- PHP 上传错误码
- `UPLOAD_ERR_OK`
- 文件大小限制
- `finfo`
- MIME 类型检查
- `getimagesize()`
- `random_bytes()`
- `bin2hex()`
- `move_uploaded_file()`
- 为什么不能直接信任原始文件名和扩展名

# 1. 文件上传和普通 POST 有什么不同

普通文本表单：

```html
<form method="post">
```

上传文件必须加入：

```html
enctype="multipart/form-data"
```

完整形式：

```html
<form
    method="post"
    enctype="multipart/form-data"
>
```

否则文件内容不会按文件上传格式发送。

---

# 2. input type="file"

HTML：

```html
<input
    type="file"
    name="image"
>
```

其中：

```text
name="image"
```

对应 PHP：

```php
$_FILES['image']
```

这一点和普通表单：

```text
name
↓
$_POST
```

非常类似。

---

# 3. $_FILES

文件上传后，PHP 会提供类似：

```php
$_FILES['image']
```

其中包含：

```text
name
type
tmp_name
error
size
```

可以简单理解为：

```text
原始文件名
浏览器报告的类型
服务器临时文件路径
上传错误码
文件大小
```

---

# 4. tmp_name

上传文件不会一开始就直接放到：

```text
uploads/
```

而是先进入服务器的临时上传目录。

PHP 给我们：

```php
$file['tmp_name']
```

然后程序决定：

```text
是否接受
↓
保存到哪里
```

---

# 5. error

本实验先检查：

```php
$file['error']
```

正常上传：

```php
UPLOAD_ERR_OK
```

常见错误包括：

```text
UPLOAD_ERR_INI_SIZE
文件超过 php.ini 限制

UPLOAD_ERR_PARTIAL
只上传了一部分

UPLOAD_ERR_NO_FILE
没有选择文件
```

因此上传处理的第一步通常是：

```text
先检查上传过程本身有没有错误
```

---

# 6. 文件大小检查

本实验限制：

```php
2 * 1024 * 1024
```

即：

```text
2 MB
```

PHP：

```php
if ($file['size'] > $maxSize) {
    // 拒绝
}
```

注意服务器本身还有：

```text
upload_max_filesize
post_max_size
```

等 PHP 配置限制。

程序限制和 PHP 配置限制应该共同考虑。

---

# 7. 不要相信原始扩展名

用户上传：

```text
photo.jpg
```

并不能证明它真的就是 JPEG 图片。

文件名可以被修改。

因此不要仅仅：

```text
看到 .jpg
↓
就相信是图片
```

---

# 8. MIME 类型检查

本实验使用：

```php
$finfo = new finfo(FILEINFO_MIME_TYPE);

$mimeType = $finfo->file($tmpName);
```

PHP 会根据实际文件内容判断 MIME 类型。

只允许：

```php
[
    'image/jpeg' => 'jpg',
    'image/png'  => 'png',
    'image/webp' => 'webp',
]
```

---

# 9. 为什么扩展名由服务器决定

检测结果：

```text
image/jpeg
```

程序决定：

```text
.jpg
```

而不是读取用户原始：

```text
filename.jpg
```

这样可以降低：

```text
伪造扩展名
恶意文件名
路径问题
```

带来的风险。

---

# 10. getimagesize()

本实验还增加：

```php
getimagesize($tmpName)
```

用来进一步确认：

```text
这个文件是否可以识别为图片
```

这是第二层简单检查。

---

# 11. 为什么不允许 SVG

SVG 是图片格式，但它本质上是 XML 文本，并可能包含脚本或其他主动内容。

如果上传后直接在网页中公开展示，安全处理会比普通 JPG / PNG / WebP 更复杂。

所以这个基础实验暂时只允许：

```text
JPG
PNG
WebP
```

不增加额外复杂度。

---

# 12. 为什么不用原始文件名

不推荐：

```php
$target = 'uploads/' . $_FILES['image']['name'];
```

原因包括：

```text
文件名重复
特殊字符
路径风险
恶意文件名
不可控扩展名
```

本实验使用：

```php
random_bytes(16)
```

再：

```php
bin2hex()
```

生成随机文件名。

---

# 13. random_bytes()

例如：

```php
random_bytes(16)
```

生成随机二进制数据。

再：

```php
bin2hex(...)
```

得到适合作为文件名的十六进制字符串。

例如：

```text
92bb2e73f38d...
```

最终：

```text
92bb2e73f38d....jpg
```

---

# 14. move_uploaded_file()

验证完成后：

```php
move_uploaded_file(
    $tmpName,
    $targetPath
)
```

负责：

```text
PHP 临时上传文件
↓
移动到正式 uploads 目录
```

这是 PHP 文件上传中非常核心的函数。

---

# 15. 为什么不能直接使用 rename()

对于 HTTP 上传文件，应该优先使用：

```php
move_uploaded_file()
```

因为它会确认源文件确实是通过 PHP HTTP POST 上传机制得到的文件。

---

# 16. uploads 目录必须可写

PHP 要保存文件：

```text
uploads/
```

服务器进程必须具有适当写权限。

如果保存失败，需要检查：

```text
目录权限
文件所有者
PHP 运行用户
主机安全策略
```

不要简单为了省事把生产目录全部设置成过宽权限。

---

# 17. 上传目录的另一个重要安全问题

生产环境还应尽可能确保：

> 上传目录中的文件不能被服务器当成 PHP、CGI 等脚本执行。

具体做法取决于：

```text
Apache
Nginx
主机控制面板
部署环境
```

本基础实验不加入服务器专属配置文件，避免把实验绑定到某一种服务器。

---

# 18. accept 不能当作安全验证

HTML：

```html
accept=".jpg,.png,.webp"
```

只是：

```text
帮助用户在文件选择器里筛选文件
```

它不是服务器安全措施。

用户仍然可以构造请求上传其他文件。

真正决定是否接受文件的是：

```text
PHP 服务器端检查
```

# 21. 与数据库的关系

文件本身通常不会直接保存到数据库。

更常见的是：

```text
图片文件
↓
uploads/

数据库
↓
保存文件路径 / URL / 元数据
```

例如：

```text
products
│
├── id
├── name
└── image
      ↓
uploads/abc123.jpg
```

后面的数据库实验会逐渐连接这些知识。

# 本章重点

最重要的不是：

```text
把文件传上去
```

而是形成：

```text
任何上传文件
↓
都属于外部输入
↓
先验证
↓
再决定是否保存
```

并牢记：

```text
不要相信：
原始文件名
扩展名
浏览器报告的 MIME
```
