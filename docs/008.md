# 实验 08：PHP POST 表单提交

本实验通过一个极简联系表单，学习浏览器如何使用 POST 向 PHP 提交数据。

## 实验目标

完成本实验后，应能够理解：

- `<form method="post">`
- `$_POST`
- `$_SERVER['REQUEST_METHOD']`
- `??`
- `trim()`
- 表单字段的 `name`
- POST 提交后 PHP 如何读取数据
- GET 与 POST 的基本区别
- 为什么输出用户输入时仍然要做 HTML 转义

## 1. POST 表单

HTML：

```html
<form method="post">
```

代表：

```text
这个表单提交时
↓
使用 POST 请求
```

---

## 2. name 属性非常重要

例如：

```html
<input name="email">
```

提交后 PHP 才能通过：

```php
$_POST['email']
```

获取这个字段。

可以理解为：

```text
HTML name
↓
POST 参数名
↓
$_POST 数组键名
```

---

## 3. $_POST 是什么

`$_POST` 是 PHP 的超全局数组。

假设表单提交：

```text
name = Tom
email = tom@example.com
```

PHP 中可以理解为：

```php
$_POST = [
    'name' => 'Tom',
    'email' => 'tom@example.com',
];
```

于是可以：

```php
$name = $_POST['name'];
$email = $_POST['email'];
```

---

## 4. 本实验为什么使用 ??

本实验写：

```php
$name = $_POST['name'] ?? '';
```

意思是：

```text
如果 name 存在
↓
使用提交值

否则
↓
使用空字符串
```

这样可以避免直接访问不存在的数组键。

---

## 5. 判断当前是不是 POST 请求

本实验使用：

```php
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    // 处理表单
}
```

可以理解为：

```text
如果当前请求方法是 POST
↓
才执行表单处理逻辑
```

第一次直接打开页面通常是：

```text
GET
```

点击提交按钮后：

```text
POST
```

因此同一个 `index.php` 可以同时负责：

```text
显示表单
+
处理表单
```

## 6. trim()

本实验继续使用：

```php
trim()
```

例如：

```php
$name = trim($_POST['name'] ?? '');
```

作用是去掉字符串两边多余的空格。

## 7. POST 与 GET 的核心区别

### GET

参数通常显示在 URL 中：

```text
index.php?keyword=WPC
```

适合：

```text
搜索
筛选
排序
分页
查看数据
```

---

### POST

参数通常不会直接显示在 URL 中：

```text
index.php
```

数据放在 HTTP 请求体中发送。

更适合：

```text
联系表单
登录
注册
新增数据
修改数据
提交留言
```

---

## 8. POST 并不等于“绝对安全”

这是一个非常重要的认识。

POST 只是：

> 数据没有直接出现在 URL 查询字符串里。

但这并不代表数据天然安全。

真实项目仍然需要：

```text
HTTPS
输入验证
权限检查
CSRF 防护
数据库预处理
输出转义
```

这些会在后续实验逐步学习。

---

## 9. 为什么输出时仍然使用 htmlspecialchars()

用户提交：

```text
姓名
邮箱
留言
```

都属于外部输入。

因此不要直接：

```php
<?= $name ?>
```

而应该：

```php
<?= e($name) ?>
```

本实验中的：

```php
e()
```

实际封装了：

```php
htmlspecialchars()
```

---

## 10. textarea 为什么这样写

输入框：

```html
<input value="...">
```

而多行文本框：

```html
<textarea>内容</textarea>
```

因此 PHP 回填留言时写：

```php
<textarea><?= e($message) ?></textarea>
```

---

## 11. nl2br()

留言中可能有换行。

HTML 默认不会直接显示文本中的普通换行。

因此本实验使用：

```php
nl2br()
```

把换行转换为：

```html
<br>
```

因为先执行：

```php
e($message)
```

再执行：

```php
nl2br()
```

所以仍然保持安全输出。

## 12. 一个完整 POST 流程

本章最重要的链路：

```text
用户填写 HTML 表单
↓
点击提交
↓
浏览器发送 POST
↓
PHP 检查 REQUEST_METHOD
↓
$_POST 获取数据
↓
PHP 处理数据
↓
页面显示结果
```

## GET 和 POST 简单对照

| 场景 | GET | POST |
|---|---:|---:|
| 搜索 | 推荐 | 一般不需要 |
| 筛选 | 推荐 | 一般不需要 |
| 分页 | 推荐 | 一般不需要 |
| 登录 | 不推荐 | 推荐 |
| 联系表单 | 不推荐 | 推荐 |
| 新增数据库记录 | 不推荐 | 推荐 |
| 修改数据 | 不推荐 | 推荐 |

这只是基础阶段的使用原则，并不是 HTTP 设计的全部内容。
