# 实验 19：PHP JSON API

本实验把 PHP 从：

```text
直接生成 HTML
```

切换成：

```text
返回 JSON
```

然后由 JavaScript：

```text
fetch()
```

请求 PHP API，并把 JSON 数据渲染到页面。

---

## 实验目标

完成本实验后，应能够理解：

- 什么是 JSON API
- `Content-Type: application/json`
- `json_encode()`
- HTTP 状态码
- API 响应结构
- `fetch()`
- `response.json()`
- GET 参数
- PDO 查询
- PHP 数组 → JSON
- JSON → JavaScript Object
- 前端与后端为什么可以分开

# 3. JSON API 的最基本结构

PHP：

```php
header(
    'Content-Type: application/json; charset=UTF-8'
);

echo json_encode($data);
```

这样浏览器收到的就不是普通 HTML，而是：

```json
{
  "success": true,
  "data": []
}
```

---

# 4. Content-Type

API 返回 JSON 时应该明确：

```php
header(
    'Content-Type: application/json; charset=UTF-8'
);
```

告诉客户端：

```text
这不是 HTML
这是 JSON
```

---

# 5. 统一响应结构

本实验成功响应：

```json
{
  "success": true,
  "message": "查询成功。",
  "count": 8,
  "data": []
}
```

失败：

```json
{
  "success": false,
  "message": "数据库连接或查询失败。",
  "data": []
}
```

这样前端可以统一判断：

```js
if (data.success === true) {
    // 成功
}
```

---

# 6. respond() 函数

本实验封装：

```php
respond()
```

统一处理：

```text
HTTP 状态码
+
json_encode()
+
输出
+
exit
```

避免每个分支重复写。

# 7. HTTP 状态码

本实验使用：

```text

```

PHP：

```php

```

API 不应该所有情况都只返回：


# 11. 为什么 API 不返回 HTML

API 的目标不是：

```text
决定页面长什么样
```

而是：

```text
提供数据
```

因此：

```text
PHP API
↓
JSON

前端
↓
决定如何显示
```

这样同一个 API 甚至可以被：

```text
网页
手机 App
其他程序
```

共同调用。

---

# 12. JavaScript fetch()

前端：

```js
const response = await fetch(
    'api/products.php'
);
```

此时浏览器向 PHP API 发出 HTTP 请求。

---

# 13. response.json()

收到响应后：

```js
const data = await response.json();
```

浏览器把：

```text
JSON
```

解析成：

```text
JavaScript Object
```

于是可以：

```js
data.success
data.count
data.data
```

---

# 14. PHP 与 JavaScript 的 JSON 对应

PHP：

```php
$data = [
    'success' => true,
    'count' => 3,
];
```

经过：

```php
json_encode($data)
```

得到：

```json
{
  "success": true,
  "count": 3
}
```

JavaScript：

```js
data.success
data.count
```

这就是前后端数据交换的重要桥梁。

# 17. API 与 AJAX 的关系

传统 Ajax 的核心目标就是：

> 页面不整体刷新，也可以和服务器交换数据。

现在现代浏览器通常直接使用：

```js
fetch()
```

所以：

```text
fetch()
+
JSON API
```

就是非常常见的现代实现方式。

---

# 18. 与 WordPress REST API 的关系

WordPress 自己提供 REST API，例如：

```text
/wp-json/
```

其核心思想仍然是：

```text
HTTP 请求
↓
PHP
↓
WordPress 数据
↓
JSON
```

因此理解原生 PHP JSON API 后，再看 WordPress REST API 会容易很多。

# 20. 当前实验为什么只做 GET

本章只研究：

```text
读取 API
```

即：

```text
GET
```

暂时不加入：

```text
POST API
PUT
PATCH
DELETE
Token
认证
CORS
```

否则会把一个最小 API 实验复杂化。

---

# 21. API 安全仍然要分层

和普通 PHP 页面一样：

```text
输入
↓
验证

SQL
↓
PDO 预处理

输出
↓
JSON 编码
```

不同层解决不同问题。

---

# 22. 为什么前端不用 innerHTML 拼用户数据

本实验使用：

```js
textContent
```

来显示 API 返回内容。

这是为了避免把数据直接当 HTML 解析。

同样体现：

```text
数据
和
代码 / HTML
应该保持边界
```

# 23. 运行环境

PHP 需要启用：

```text
PDO
pdo_sqlite
```

如果当前 PHP 环境没有 `pdo_sqlite`：

```text
api/products.php
```

会返回一个 JSON 格式的 500 错误，而不是直接输出 PHP Fatal Error。
