# 实验 17：PDO 预处理与安全查询

本实验专门研究 PDO 中最重要的安全查询方式：

```text
prepare()
execute()
bindValue()
```

核心目标不是增加 CRUD 功能，而是理解：

> 为什么 SQL 结构和用户输入必须分开。

# 1. 为什么这一章必须单独学习

上一章 CRUD 已经使用：

```php
prepare()
execute()
```

但如果只是照着写，很容易变成：

```text
会用
但不知道为什么
```

所以这一章专门把它拆开。

---

# 2. 最危险的思路：直接拼接用户输入

例如：

```php
$keyword = $_GET['keyword'];

$sql = "
    SELECT *
    FROM products
    WHERE name = '$keyword'
";
```

问题在于：

```text
SQL 代码
+
用户输入
```

被直接拼成了同一个字符串。

这会让数据库难以区分：

```text
哪部分是 SQL
哪部分只是普通数据
```

从而产生 SQL 注入风险。

---

# 3. 正确思路：SQL 和数据分离

先写 SQL 结构：

```php
$statement = $pdo->prepare(
    'SELECT *
     FROM products
     WHERE name = :name'
);
```

再传数据：

```php
$statement->execute([
    ':name' => $name,
]);
```

这样可以理解为：

```text
第一步
固定 SQL 结构

第二步
把用户输入当作数据传入
```

---

# 4. 什么是占位符

SQL：

```sql
WHERE name = :name
```

其中：

```text
:name
```

就是占位符。

它暂时代表：

```text
这里以后会放一个参数值
```

---

# 5. 命名占位符

本实验主要使用：

```text
:name
:id
:keyword
```

优点是代码容易读。

例如：

```sql
WHERE id = :id
```

一眼就能看出：

```text
:id
对应产品 ID
```

---

# 6. execute()

最常见写法：

```php
$statement->execute([
    ':name' => $name,
    ':model' => $model,
]);
```

适合：

```text
一次性传入多个参数
```

---

# 7. bindValue()

另一种方式：

```php
$statement->bindValue(
    ':id',
    $id,
    PDO::PARAM_INT
);

$statement->execute();
```

这里可以明确告诉 PDO：

```text
:id
是整数
```

---

# 8. PDO::PARAM_INT

用于整数参数：

```php
PDO::PARAM_INT
```

例如：

```text
产品 ID
页码
数量
状态整数
```

---

# 9. PDO::PARAM_STR

用于字符串参数：

```php
PDO::PARAM_STR
```

例如：

```text
产品名称
关键词
邮箱
型号
```

示例：

```php
$statement->bindValue(
    ':keyword',
    $keyword,
    PDO::PARAM_STR
);
```

---

# 10. execute() 数组和 bindValue() 如何选择

简单场景：

```php
$statement->execute([
    ':name' => $name,
]);
```

更简洁。

如果需要：

```text
明确参数类型
逐个绑定
更精细控制
```

可以使用：

```php
bindValue()
```

两种方式都很常见。

---

# 11. 本实验的关键词搜索

SQL：

```sql
SELECT id, name, model, price
FROM products
WHERE name LIKE :keyword
   OR model LIKE :keyword
```

PHP：

```php
$statement->execute([
    ':keyword' => '%' . $keyword . '%',
]);
```

于是用户输入：

```text
WPC
```

真正参数是：

```text
%WPC%
```

表示：

```text
前面可以有内容
后面可以有内容
```

---

# 12. LIKE 里的 % 是什么

SQL：

```text
%
```

代表通配符。

例如：

```text
%WPC%
```

可以匹配：

```text
Classic WPC Decking
WPC Wall Panel
Outdoor WPC Product
```

---

# 13. ID 查询为什么用整数验证

URL：

```text
?id=1
```

属于用户输入。

本实验使用：

```php
filter_input(
    INPUT_GET,
    'id',
    FILTER_VALIDATE_INT
)
```

先确认：

```text
它确实是整数
```

再：

```php
bindValue(
    ':id',
    $id,
    PDO::PARAM_INT
);
```

这是两个不同层次：

```text
输入验证
+
数据库参数绑定
```

---

# 14. 验证不能替代预处理

即使我们已经验证：

```text
id 是整数
```

数据库查询仍然应该使用：

```php
prepare()
```

因为：

```text
验证
```

解决的是：

```text
数据是否符合业务要求
```

而：

```text
预处理
```

解决的是：

```text
SQL 和数据如何安全交互
```

两者不是同一件事。

---

# 15. htmlspecialchars() 也不能替代预处理

这是另一个容易混淆的问题。

```php
htmlspecialchars()
```

解决：

```text
HTML 输出安全
```

预处理解决：

```text
SQL 查询安全
```

所以：

```text
htmlspecialchars()
≠
SQL 防注入
```

---

# 16. 三种安全概念要分开

可以整理成：

```text
输入验证
↓
数据是否合法

PDO 预处理
↓
SQL 是否安全

htmlspecialchars()
↓
HTML 输出是否安全
```

这是 PHP Web 开发里非常重要的三层认识。

---

# 17. SQL 注入本质是什么

可以把 SQL 注入理解为：

> 程序错误地把用户输入的一部分，当成了 SQL 语法。

根本问题：

```text
代码
和
数据

没有分开
```

预处理的核心价值就是帮助我们保持这种边界。

---

# 18. 预处理不仅用于 SELECT

同样适用于：

```text
INSERT
UPDATE
DELETE
SELECT
```

例如新增：

```sql
INSERT INTO products (
    name,
    price
)
VALUES (
    :name,
    :price
)
```

修改：

```sql
UPDATE products
SET name = :name
WHERE id = :id
```

删除：

```sql
DELETE FROM products
WHERE id = :id
```

# 20. 与 WordPress 的关系

WordPress 使用：

```php
$wpdb->prepare()
```

例如：

```php
$wpdb->prepare(
    'SELECT * FROM table WHERE id = %d',
    $id
);
```

虽然 API 不同，但核心思想完全相同：

```text
SQL 结构
+
参数
↓
分开处理
```
