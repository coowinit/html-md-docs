# 实验 06：PHP 页面模块化

本实验开始进入 PHP Web 开发阶段。

核心目标是把一个完整页面拆分成多个可复用文件，理解：

- `include`
- `require`
- `include_once`
- `require_once`
- `__DIR__`
- 公共头部
- 公共底部
- 配置文件
- 公共函数文件
- 多页面复用

---

## 文件结构

```text
06-php-include/
├── index.php
├── about.php
├── README.md
└── includes/
    ├── config.php
    ├── functions.php
    ├── header.php
    └── footer.php
```

---

# 1. 为什么需要页面模块化

如果网站有：

```text
首页
关于我们
产品页
联系页
```

这些页面通常都会拥有相同的：

```text
HTML 头部
导航
底部
```

如果每个页面都完整复制一遍：

```text
header HTML
navigation HTML
footer HTML
```

后面修改导航时，就需要修改很多文件。

更合理的结构是：

```text
header.php
footer.php
```

然后其他页面加载它们。

---

# 2. include

最基本的写法：

```php
include 'header.php';
```

PHP 会：

```text
读取 header.php
↓
把它放到当前位置
↓
继续执行页面
```

本实验使用：

```php
include __DIR__ . '/includes/header.php';
```

这样路径更明确。

---

# 3. require

写法：

```php
require 'config.php';
```

`require` 与 `include` 的核心用途类似：

```text
加载另外一个 PHP 文件
```

但如果目标文件不存在，两者处理方式不同。

## include

文件加载失败时，会产生警告，但脚本通常还会继续执行。

## require

文件加载失败时，会导致致命错误，脚本停止执行。

因此像：

```text
配置文件
数据库文件
公共函数
```

这些“缺少后程序就无法正常工作”的文件，更适合使用：

```php
require
```

---

# 4. include_once 和 require_once

如果某个文件被重复加载：

```php
include 'functions.php';
include 'functions.php';
```

可能导致函数重复定义。

因此公共函数文件通常使用：

```php
require_once 'functions.php';
```

`once` 的意思是：

> 同一个文件在当前请求中只加载一次。

---

# 5. 本实验为什么这样选择

本实验：

```php
require_once __DIR__ . '/includes/config.php';
require_once __DIR__ . '/includes/functions.php';
```

因为：

```text
配置
+
函数
```

都是页面运行的重要依赖。

而：

```php
include __DIR__ . '/includes/header.php';
include __DIR__ . '/includes/footer.php';
```

主要负责页面结构。

这样可以很直观地比较两种用途。

---

# 6. __DIR__ 是什么

PHP 中：

```php
__DIR__
```

代表：

> 当前 PHP 文件所在目录。

例如：

```php
require_once __DIR__ . '/includes/config.php';
```

比单纯写：

```php
require_once 'includes/config.php';
```

在多层目录项目中通常更稳定、更容易理解路径来源。

---

# 7. config.php

本实验把站点公共配置放到：

```text
includes/config.php
```

例如：

```php
const SITE_NAME = 'PHP Development Lab';
const SITE_VERSION = '1.0.0';
```

其他页面只需要加载：

```php
require_once __DIR__ . '/includes/config.php';
```

即可使用。

---

# 8. functions.php

公共函数放到：

```text
includes/functions.php
```

例如：

```php
function e(string $value): string
{
    return htmlspecialchars(
        $value,
        ENT_QUOTES,
        'UTF-8'
    );
}
```

以后如果多个页面都需要 `e()`，不需要重复定义。

---

# 9. header.php 和 footer.php

页面可以变成：

```php
<?php include 'header.php'; ?>

<main>
    当前页面自己的内容
</main>

<?php include 'footer.php'; ?>
```

这样就形成：

```text
公共头部
↓
当前页面内容
↓
公共底部
```

---

# 10. 两个页面共用同一套模块

本实验提供：

```text
index.php
about.php
```

两个页面都加载：

```text
header.php
footer.php
config.php
functions.php
```

因此可以直接观察：

> 两个不同页面如何共享同一套公共结构。

---

# 11. 与 WordPress 的关系

WordPress 主题中非常常见：

```php
get_header();
get_footer();
get_sidebar();
get_template_part();
```

思想与本实验非常接近：

```text
不要把所有代码写进一个 PHP 文件

而是：

页面模板
+
公共模块
+
可复用组件
```

例如：

```php
get_header();
```

可以理解为 WordPress 已经帮我们封装好的“加载 header.php”的机制。

---

# 12. 与长期维护的关系

如果导航发生变化：

## 没有模块化

可能需要修改：

```text
index.php
about.php
product.php
contact.php
...
```

## 模块化以后

只修改：

```text
header.php
```

即可。

这就是：

```text
少重复
↓
少修改
↓
少出错
↓
更容易长期维护
```

# 本章重点

这一章最重要的是形成：

```text
公共代码
↓
单独拆出文件

业务页面
↓
只负责自己的内容

需要公共代码
↓
include / require
```

这是 PHP 从“代码片段”进入“项目结构”的第一个关键节点。
