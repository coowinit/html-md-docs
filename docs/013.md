# 1. Cookie 是什么

可以先把 Cookie 理解为：

> 浏览器为某个网站保存的一小段数据。

例如：

```text
theme = dark
```

下次访问同一个网站时，浏览器可以自动把这条 Cookie 发给服务器。

---

# 2. setcookie()

最简单的写法：

```php
setcookie(
    'theme',
    'dark'
);
```

表示：

```text
Cookie 名称
theme

Cookie 值
dark
```

---

# 3. Cookie 不只是 name 和 value

本实验使用现代 PHP 的数组参数：

```php
setcookie(
    $cookieName,
    $newTheme,
    [
        'expires' => ...,
        'path' => '/',
        'secure' => ...,
        'httponly' => true,
        'samesite' => 'Lax',
    ]
);
```

这些选项决定 Cookie 的作用范围和安全属性。

---

# 4. expires

本实验设置：

```php
time() + 60 * 60 * 24 * 30
```

代表：

```text
当前时间
+
30 天
```

所以 Cookie 大约保存 30 天。

如果不设置持久有效期，Cookie 通常会更接近“会话 Cookie”。

---

# 5. path

本实验使用：

```php
'path' => '/'
```

代表：

> 当前域名下的整个网站都可以携带这条 Cookie。

如果只想让某个目录使用，可以设置更具体的路径。

---

# 6. secure

本实验根据当前是否 HTTPS 设置：

```php
'secure' => ...
```

如果：

```text
secure = true
```

浏览器只会通过 HTTPS 发送这条 Cookie。

真实正式网站通常应该使用 HTTPS。

---

# 7. httponly

本实验设置：

```php
'httponly' => true
```

代表：

> JavaScript 不能通过普通 `document.cookie` 读取这条 Cookie。

这是 Cookie 的一个重要安全属性。

本实验的主题偏好其实并不一定必须设置 HttpOnly，但这里保留它，是为了学习服务器端 Cookie 的安全选项。

---

# 8. samesite

本实验设置：

```php
'samesite' => 'Lax'
```

SameSite 用于限制 Cookie 在跨站请求中的发送行为。

它是现代 Web Cookie 安全的重要组成部分。

当前基础阶段只需要知道：

```text
SameSite
↓
帮助控制跨站请求时 Cookie 是否发送
```

---

# 9. $_COOKIE

PHP 可以通过：

```php
$_COOKIE['php_lab_theme']
```

读取浏览器发送来的 Cookie。

例如：

```text
浏览器保存：
php_lab_theme = dark
```

PHP：

```php
$_COOKIE['php_lab_theme']
```

得到：

```text
dark
```

---

# 10. 为什么要设置默认值

第一次访问时，浏览器还没有 Cookie。

所以本实验写：

```php
$theme = $_COOKIE[$cookieName] ?? 'light';
```

意思是：

```text
Cookie 存在
↓
读取 Cookie

Cookie 不存在
↓
使用 light
```

---

# 11. 为什么还要验证 Cookie 值

Cookie 在浏览器中保存，用户可以修改它。

因此不能直接相信：

```php
$_COOKIE
```

本实验只允许：

```php
light
dark
```

所以使用：

```php
in_array(
    $theme,
    $allowedThemes,
    true
)
```

如果值不合法，就恢复：

```text
light
```

这说明：

> Cookie 也是外部输入，不能直接信任。

---

# 12. setcookie() 后为什么 $_COOKIE 不自动变化

这是很容易困惑的一点。

```php
setcookie(...)
```

做的事情是：

```text
告诉浏览器：
请在响应完成后保存 Cookie
```

而：

```php
$_COOKIE
```

代表：

```text
浏览器在这一次请求开始时发送过来的 Cookie
```

所以当前请求中：

```php
setcookie()
```

不会自动修改：

```php
$_COOKIE
```

新的 Cookie 通常会在下一次请求中出现。

本实验为了让页面立即变化，直接同步修改：

```php
$theme = $newTheme;
```

---

# 13. 删除 Cookie

删除 Cookie 的常见方式：

```php
setcookie(
    $name,
    '',
    [
        'expires' => time() - 3600,
        ...
    ]
);
```

也就是：

```text
把有效期设置到过去
```

浏览器就会删除 Cookie。

---

# 14. Cookie 与普通 PHP 变量

普通变量：

```php
$theme = 'dark';
```

只存在当前 PHP 请求。

页面刷新以后：

```text
变量重新开始
```

Cookie：

```text
浏览器保存
↓
下一次请求继续发送
```

因此可以跨请求保留状态。

---

# 15. Cookie 与 Session 的区别

## Cookie

主要数据通常在：

```text
浏览器
```

例如：

```text
theme = dark
language = zh-CN
```

---

## Session

主要数据通常在：

```text
服务器
```

浏览器一般只保存：

```text
Session ID
```

---

# 16. 两者其实经常一起工作

PHP Session 默认情况下常见流程：

```text
浏览器 Cookie
保存 Session ID

↓

服务器
根据 Session ID
找到 Session 数据
```

所以：

```text
Cookie
和
Session
```

不是互相排斥的技术。

Session 本身经常借助 Cookie 来识别浏览器。

---

# 17. Cookie 适合保存什么

适合：

```text
语言偏好
主题偏好
是否关闭提示
少量非敏感标记
Session ID
```

---

# 18. Cookie 不应该保存什么

不应该直接保存：

```text
明文密码
银行卡信息
敏感隐私数据
可信权限判断
```

原因很重要：

> Cookie 位于客户端环境，用户可以查看、删除甚至修改某些 Cookie。

因此服务器不能因为 Cookie 写着：

```text
role = admin
```

就直接相信用户真的是管理员。

---

# 19. Cookie 不是数据库

Cookie 应该用于：

```text
少量客户端状态
```

而不是：

```text
大量业务数据
文章
产品
订单
用户完整资料
```

这些应该交给：

```text
SQLite
MySQL
数据库
```

---

# 20. 当前几种数据保存方式对比

```text
TXT
↓
简单文本业务数据

JSON
↓
结构化业务数据

Session
↓
服务器端当前会话状态

Cookie
↓
浏览器端少量状态
```

这四种方式已经可以明显区分了。

---

# 21. 与 WordPress 的关系

WordPress 会大量使用 Cookie，例如：

```text
登录状态
认证相关信息
后台用户会话
```

不过 WordPress 自己提供完整的认证机制。

开发 WordPress 时不应该自己随意用普通 Cookie 替代 WordPress 的用户认证系统。

---

# 22. 与 WooCommerce 的关系

电商系统也会使用：

```text
Cookie
Session
数据库
```

共同保存不同层次的数据。

例如：

```text
浏览器标识
购物会话
客户状态
购物车
订单
```

不同数据应该存到合适的位置，而不是全部放在同一种存储中。
