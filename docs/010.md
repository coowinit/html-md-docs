# 实验 10：PHP 文件读取与写入

本实验正式进入 PHP 数据存储阶段。

通过一个最小留言示例，把用户提交的数据保存到 TXT 文件中，再由 PHP 读取并显示。

---

## 实验目标

完成本实验后，应能够理解：

- `file_put_contents()`
- `file_get_contents()`
- `file_exists()`
- `FILE_APPEND`
- `LOCK_EX`
- `__DIR__`
- 文本文件写入
- 文本文件读取
- 文件追加模式
- PHP 文件权限的基本概念
- 为什么文件也可以作为一种最基础的数据存储方式

---

## 文件结构

```text
10-php-file/
├── index.php
├── README.md
└── data/
    └── messages.txt
```

`messages.txt` 初始为空。

提交表单以后，PHP 会自动向其中追加内容。

# 1. 从“只显示”到“真正保存”

前面的 POST 实验：

```text
表单
↓
PHP
↓
页面显示
```

刷新页面以后，数据就没有了。

本章增加一个文件：

```text
data/messages.txt
```

流程变成：

```text
表单
↓
PHP
↓
文件
```

于是数据可以继续保留。

---

# 2. file_put_contents()

最简单的写文件方式：

```php
file_put_contents(
    'message.txt',
    'Hello PHP'
);
```

PHP 会把：

```text
Hello PHP
```

写入文件。

---

# 3. 默认写入会覆盖旧内容

如果连续执行：

```php
file_put_contents(
    'message.txt',
    'A'
);
```

然后：

```php
file_put_contents(
    'message.txt',
    'B'
);
```

最终文件通常只剩：

```text
B
```

因为默认模式会覆盖旧内容。

---

# 4. FILE_APPEND

如果希望保留旧内容并继续追加：

```php
file_put_contents(
    $file,
    $content,
    FILE_APPEND
);
```

例如：

```text
第一条
第二条
第三条
```

都会保留下来。

这就是：

```text
追加写入
```

---

# 5. LOCK_EX

本实验使用：

```php
FILE_APPEND | LOCK_EX
```

其中：

```php
LOCK_EX
```

表示写入时请求独占锁。

可以简单理解为：

> 写文件时，尽量避免多个请求同时写入造成冲突。

它不能替代完整的数据库并发机制，但对于简单文件实验非常有价值。

---

# 6. file_get_contents()

读取整个文件：

```php
$content = file_get_contents(
    $file
);
```

成功时返回：

```text
文件内容字符串
```

失败时返回：

```php
false
```

因此真实代码应判断：

```php
if ($content !== false) {
    // 使用内容
}
```

---

# 7. file_exists()

读取文件前可以先判断：

```php
file_exists($file)
```

例如：

```php
if (file_exists($dataFile)) {
    // 读取文件
}
```

这样可以避免直接读取一个不存在的文件。

---

# 8. __DIR__

本实验使用：

```php
$dataFile = __DIR__
    . '/data/messages.txt';
```

`__DIR__` 代表：

```text
当前 PHP 文件所在目录
```

因此无论当前脚本从哪里调用，都可以更稳定地定位：

```text
data/messages.txt
```

---

# 9. PHP_EOL

每次留言后增加：

```php
PHP_EOL
```

表示：

```text
当前系统对应的换行符
```

这样每条记录都会单独占一行。

---

# 10. 为什么删除留言中的换行

本实验保存前使用：

```php
str_replace(
    ["\r", "\n"],
    ' ',
    $message
)
```

因为我们当前定义：

```text
一行 = 一条留言
```

如果留言本身包含多行，就会破坏这个简单结构。

所以第一版先把留言中的换行转换为空格。

---

# 11. 文件内容为什么仍要安全输出

即使数据已经保存进 TXT 文件，它最初仍然来自用户输入。

因此读取后不能直接：

```php
<?= $fileContent ?>
```

而是：

```php
<?= e($fileContent) ?>
```

也就是：

```text
用户输入
↓
TXT
↓
读取
↓
htmlspecialchars()
↓
HTML
```

数据经过文件保存，并不会自动变成可信数据。

---

# 12. TXT 文件适合什么场景

简单文件存储适合：

```text
学习实验
简单日志
少量配置
极小型数据
临时记录
```

例如：

```text
访问日志
调试日志
简单计数器
极简留言记录
```

---

# 13. TXT 文件不适合什么

如果数据开始需要：

```text
搜索
修改
删除
排序
分页
关联
大量记录
多人并发
```

TXT 就会越来越难维护。

这时应该考虑：

```text
JSON
SQLite
MySQL
```

---

# 14. 文件与数据库的区别

TXT 的思路：

```text
PHP
↓
整个文件
↓
自己解释里面的文本
```

数据库的思路：

```text
PHP
↓
SQL
↓
数据库管理系统
↓
按字段和记录管理数据
```

所以数据库提供了更强的数据结构和查询能力。

---

# 15. 文件权限

PHP 要写入：

```text
data/messages.txt
```

服务器上的 PHP 进程必须对：

```text
data/
```

或目标文件具有写权限。

如果出现：

```text
Permission denied
```

通常就需要检查：

```text
目录权限
文件权限
PHP 运行用户
主机安全设置
```

不应该为了省事直接把所有目录设置成过宽权限。

---

# 16. 为什么本章先用 TXT

如果一开始直接学习数据库，很容易只记住：

```text
PDO
SQL
INSERT
SELECT
```

却没有真正理解：

> PHP 最终是在把数据保存到某种持久化介质中。

TXT 是最容易看见、最容易打开、最容易理解的数据存储形式。

因此路线是：

```text
TXT
↓
JSON
↓
Session / Cookie
↓
SQLite
↓
数据库 CRUD
```
