# 实验 16：PHP + SQLite CRUD

本实验把前面学习的 PHP 基础、表单、模块化、PDO 和 SQLite 连接成一个最小产品管理系统。

CRUD：

```text
Create  → 新增
Read    → 查看
Update  → 修改
Delete  → 删除
```

---

## 实验目标

完成本实验后，应能够理解：

- CRUD 是什么
- PHP 表单如何新增数据库记录
- 如何读取数据库列表
- 如何根据 `id` 查询单条记录
- 如何修改记录
- 如何删除记录
- 为什么新增 / 修改 / 删除通常使用 POST
- 为什么删除不应该直接使用普通 GET 链接
- `prepare()` / `execute()` 在 CRUD 中的基本用法
- Post / Redirect / Get 的简单思想
- 如何把数据库连接、函数、头部和底部拆分成公共文件

# 1. CRUD 是什么

CRUD 是绝大多数数据管理系统最基本的四种操作。

```text
Create
新增数据

Read
读取数据

Update
修改数据

Delete
删除数据
```

例如产品后台：

```text
新增产品
查看产品
修改产品
删除产品
```

就是标准 CRUD。

# 5. Create：新增记录

用户填写：

```text

```

```text

↓

↓
```

```sql

    price,
    created_at
)
VALUES (
    :name,
    :model,
    :price,
    :created_at

```

# 6. 为什么 CRUD 中已经使用 prepare()

下一章才会专门研究 PDO 预处理，但本章已经必须使用：

```php
prepare()
execute()
```

原因是：

> CRUD 已经开始处理真实用户输入。

不能为了教学顺序，把用户输入直接拼接到 SQL。

因此本章先“正确使用”，下一章再专门拆解其原理。

# 7. 参数占位符

SQL 中：

```sql
:name
:model
:price
```

不是最终数据。

真正的数据在：

```php
$statement->execute([
    ':name' => $name,
    ':model' => $model,
    ':price' => (float) $price,
]);
```

传入。

可以先理解成：

```text
SQL 结构
和
用户数据

分开处理
```

---

# 8. Update：编辑记录

访问：

```text
edit.php?id=2
```

首先根据：

```text
id = 2
```

查询这一条产品。

SQL：

```sql
SELECT ...
FROM products
WHERE id = :id
```

获得原数据后回填表单。

用户修改后：

```sql
UPDATE products
SET
    name = :name,
    model = :model,
    price = :price
WHERE id = :id
```

---

# 9. 为什么 id 需要验证

本实验使用：

```php
filter_input(
    INPUT_GET,
    'id',
    FILTER_VALIDATE_INT
)
```

因为：

```text
?id=...
```

属于外部输入。

我们希望产品 ID 是：

```text
整数
```

所以应该先验证。

# 10. Delete：删除记录

SQL：

```sql
DELETE FROM products
WHERE id = :id
```

本实验没有使用：

```text
delete.php?id=10
```

这种普通 GET 删除方式。

而是：

```text
POST
↓
delete.php
```

---

# 11. 为什么删除不建议用 GET

GET 更适合：

```text
读取
查看
搜索
分页
```

删除会改变服务器数据。

如果直接：

```text
GET /delete.php?id=10
```

浏览器预加载、爬虫、误点击等都可能增加风险。

因此改变数据的操作更适合：

```text
POST
```

更完整的 REST 系统还会使用：

```text
PUT
PATCH
DELETE
```

但普通 PHP HTML 表单主要还是 GET / POST。

---

# 12. 删除确认不是服务器安全措施

页面使用：

```js
confirm(...)
```

只是改善用户体验，防止误点。

它不是服务器端安全验证。

用户完全可以绕过 JavaScript。

真实项目还需要：

```text
身份验证
权限检查
CSRF 防护
```

这些不在当前基础 CRUD 实验中展开。

# 13. Post / Redirect / Get

新增成功后：

```php
redirectTo(
    'index.php?status=created'
);
```

没有直接继续输出新增页面。

流程：

```text
POST
↓
数据库写入
↓
Redirect
↓
GET 产品列表
```

这样刷新列表页时，不会轻易重新提交上一份新增表单。

这是一种很常见的 Web 开发模式：

```text
PRG
Post / Redirect / Get
```

---

# 14. 为什么数据库连接单独放 db.php

所有页面都需要：

```text
PDO
SQLite
```

因此统一放：

```text
includes/db.php
```

这样数据库路径、错误模式等只维护一次。

---

# 15. 为什么 functions.php 单独存在

本实验公共函数：

```php
e()
redirectTo()
```

统一放：

```text
includes/functions.php
```

避免：

```text
index.php 定义一次
create.php 再定义一次
edit.php 再定义一次
```

# 17. app.db

压缩包中已经包含：

```text
3 条测试产品记录
```

可以直接使用支持 SQLite 的 PHP 环境打开。

如果删除：

```text
database/app.db
```

代码会重新创建：

```text
空数据库
+
products 表
```

但不会自动重新插入测试数据。

这样你删除完所有产品后，也不会突然又重新出现测试数据。

# 20. 与 WordPress 的关系

WordPress 后台很多功能也是 CRUD：

```text
新增文章
查看文章
修改文章
删除文章
```

WooCommerce：

```text
新增产品
查看产品
修改产品
删除产品
```

只是 WordPress / WooCommerce 在 CRUD 外面又增加了：

```text
权限
Nonce
Hooks
Meta
Taxonomy
模板
缓存
业务规则
```

因此理解原生 PHP CRUD 后，再看 WordPress 会更容易明白：

> 框架和 CMS 到底替我们封装了什么。
